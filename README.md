# Weekly Routine

월~일 요일별 루틴을 5분 단위로 편집하고, 24시간짜리 원형 시계(도넛 차트)로 시현하는 개인용 루틴 앱입니다.

- **웹앱**: 순수 HTML/CSS/JS 한 파일(`index.html`)이고, GitHub Pages에 올려 노션(Notion) 등에 실제로 인라인 임베드할 수 있습니다.
- **안드로이드 앱**: 같은 웹앱에 홈 화면 위젯과 상태 변경 알림을 더한 앱입니다.
- **PC 바탕화면 위젯**: Windows 바탕화면에 오늘 루틴을 띄워 둡니다.

## 주요 기능

**편집 · 시현 (웹앱, 안드로이드 앱 공통)**
- **5분 단위 편집** — 요일마다 시작/종료 시각을 5분 단위로 지정해 블록을 추가·수정·삭제.
- **케이스(변형) 지원** — 하루에 "사무실 출근 / 재택근무 / 휴식" 같은 여러 시나리오를 만들어두고 골라서 시현.
- **24시간 원형 시계 시현** — 카테고리별 색상으로 구분된 도넛 차트. 오늘 날짜면 현재 시각 바늘도 함께 표시.
- **구간 강조** — 시계의 한 구간(예: 12:00~13:00)을 누르면 그 구간이 살짝 커지고, 가운데에 그 구간의 상태(예: "업무")와 시간대·메모가 나옴. 나머지 구간은 어둡고 흐릿해짐.
- **'지금' 상태 표시** — 루틴상 지금 해야 할 일(예: "업무 · 팀 회의, 1시간 20분 남음, 다음: 점심 12:00")을 항상 보여주고, 오늘 시계 가운데에도 현재 카테고리와 남은 시간을 표시.
- **일간 / 주간 시현 전환** — 일간은 요일 탭 + 스와이프로 요일 넘기기, 주간은 월~일을 한 줄로 두고 좌우 스크롤.
- **시간별 상태 · 카테고리별 총시간** — 시계 아래에 블록 목록(예: `00:00–07:00 수면`, 지금 블록 강조)과 카테고리별 합산 시간을 표시. 넓은 화면은 2열로 나란히, 휴대폰·주간 카드는 스위치로 전환(기본은 시간별 상태).
- **카테고리 관리** — 색상·이름을 자유롭게 편집, 사용 중인 카테고리는 삭제 방지.
- **크로스 디바이스 동기화** — Cloudflare Worker + KV에 저장해서 어느 기기에서 열어도 같은 데이터가 보임. **↻ 새로고침**으로 최신 내용을 바로 불러옴.
- **토큰 기반 편집 잠금** — 조회(시현)는 잠금 없이 가능하고, 편집은 발급받은 토큰을 입력해야 가능. 한 번 넣으면 그 기기에서는 유지됨.
- **JSON 백업** — 편집 화면 맨 아래에서 JSON 내보내기/가져오기.
- **노션 인라인 임베드** — GitHub Pages는 `X-Frame-Options`를 보내지 않아 노션에 진짜로 인라인 삽입됨.
- **다크 네이비 테마** — 색맹 접근성을 고려해 검증한 카테고리 색상 팔레트.

**안드로이드 앱 (`android/`)**
- 앱 하나로 시현·편집, 홈 화면 위젯, 상태 변경 알림을 모두 씀. 앱 안의 화면은 웹앱 그대로라 웹앱을 고치면 앱에도 바로 반영됨.
- **⚙ 알림** — 알림·소리·진동·미지정 시간 알림 설정, 권한 안내, 테스트 알림.
- **상태 변경 알림** — 루틴상 할 일이 바뀌는 순간 알림(인터넷 없어도 옴). 앱에서 저장하면 알림 예약에 바로 반영.
- **4x2 홈 화면 위젯**
  - 왼쪽: 현재 시각과 시계. 가운데에 지금 상태와 남은 시간이 나오고, 1분마다 갱신.
  - 오른쪽: 케이스 선택, '지금', 블록 목록.
  - ◀ ▶·요일 띠로 다른 요일을 볼 수 있음.
  - 목록 줄을 누르면 시계에서 그 구간을 강조.

**PC 바탕화면 위젯 (`desktop-widget/`)**
- 휴대폰 위젯과 같은 화면(현재 시각 + 시계, 케이스 선택, '지금', 블록 목록)을 바탕화면에 띄워 둠.
- 마우스로 좌우로 끌면 요일 이동, 마우스를 올리면 **앱 열기**(PC에 설치한 앱이 있으면 그 앱으로) 버튼.
- 끌어서 이동·크기 조절, Windows 시작 시 자동 실행.

**위젯 공통** — 위젯에서는 **케이스만** 바꿀 수 있음. 편집 토큰이 있으면(안드로이드: 앱에서 편집 잠금 해제 / PC: 트레이 메뉴 **편집 토큰 설정…**) 서버에 저장돼 모든 기기에 반영되고, 없으면 그 기기에서만 적용됨.

## 설치

| 대상 | 방법 |
|---|---|
| PC 브라우저 | GitHub Pages 주소를 열면 끝. 노션에는 `/embed`로 넣기 |
| 안드로이드 | [`android/README.md`](./android/README.md) — Android Studio로 APK를 빌드해 설치(앱 하나로 웹앱·위젯·알림) |
| iPhone | Safari로 열고 공유 → **"홈 화면에 추가"**(PWA, 위젯·알림 없음) |
| Windows PC 위젯 | [`desktop-widget/README.md`](./desktop-widget/README.md) — .NET 8로 exe를 빌드해 한 번 실행(자동 실행까지 등록) |

저장하면 다른 기기와 동기화되고, 저장소 코드를 고쳐 push하면 웹앱·안드로이드 앱 화면·PC 위젯 화면에 다음 실행(또는 새로고침) 때 반영됩니다. 안드로이드 앱의 네이티브 부분(위젯·알림)이나 PC 위젯 프로그램 자체를 고쳤을 때만 APK/exe를 다시 설치합니다.

> **iPhone 참고**: 홈 화면에 추가한 앱은 Safari와 저장공간이 분리되어 있어서, 처음 한 번은 앱 안에서 편집 토큰을 다시 입력해야 합니다.

## 기술 스택

| 구성 요소 | 선택 |
|---|---|
| 프론트엔드 | 순수 HTML/CSS/JS 단일 파일(`index.html`), 빌드 과정 없음 |
| 호스팅 | GitHub Pages |
| 백엔드 | Cloudflare Workers + KV (`worker/`) |
| 인증 | Bearer 토큰 1개 (쓰기만 보호) |
| 안드로이드 앱 | Kotlin — WebView로 웹앱 표시 + JS 브리지, AppWidget, AlarmManager, WorkManager (`android/`) |
| PC 위젯 | .NET 8 WinForms + WebView2 (`desktop-widget/`) |

## 폴더 구조

```
index.html            웹앱 전체(HTML+CSS+JS). 안드로이드 앱과 PC 위젯도 이 화면을 씀
manifest.webmanifest  PWA 설정(앱 이름·아이콘·전체화면)
sw.js                 서비스워커(오프라인 실행·앱 셸 캐시)
icons/                앱 아이콘(icon.svg 원본 + PNG)
demo/
  index.html           웹앱 데모(build-demo.py가 만듦 — 직접 고치지 않음)
  app.html             휴대폰 앱 데모(휴대폰 틀)
  widgets.html         PC · 휴대폰 위젯 데모
  build-demo.py        index.html → demo/index.html 변환(서버 연결·개인 데이터 제거)
worker/
  src/index.js         Cloudflare Worker API (GET/POST /state)
  wrangler.toml        Worker 설정 (KV 네임스페이스 바인딩)
android/               안드로이드 앱(웹앱 + 홈 화면 위젯 + 상태 변경 알림)
desktop-widget/        Windows 바탕화면 위젯 앱
AI-BUILD-GUIDE.md      이 앱을 다른 계정/PC에서 AI로 똑같이 재현하기 위한 전체 스펙 문서
```

`index.html`을 고친 뒤에는 `python demo/build-demo.py`로 데모를 다시 만들어 함께 커밋합니다.

## 보안 · 개인정보 노트

- 편집용 `WRITE_TOKEN`은 코드나 저장소에 절대 커밋하지 않고, Cloudflare Worker의 secret으로만 관리합니다.
- 토큰은 사용자가 입력한 기기에만 저장됩니다(브라우저 `localStorage`, 안드로이드 앱 설정). 저장 요청 때마다 `Authorization` 헤더로 보낼 뿐 코드에는 남지 않습니다.
- 저장(`POST /state`)만 토큰으로 보호되고, 조회(`GET /state`)는 의도적으로 공개되어 있습니다. 루틴을 비공개로 하려면 `AI-BUILD-GUIDE.md` 9장을 참고해 GET에도 토큰 검사를 추가하세요.
- 데모(`demo/`)는 예시 데이터만 쓰고 서버에 연결하지 않으므로, 실제 루틴이나 토큰이 데모에 노출되지 않습니다.
